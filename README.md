# BizIQ: AI-powered business intelligence and automation platform

BizIQ takes a small business's raw data (financials, sales, inventory, clients, suppliers, invoices, HR, social
and reviews), turns it into **scores, forecasts and flags**, explains them in **plain language**, and then
**acts** on them through alerts, scheduled reports and drafted communications.

> **Analytics** (what happened) → **Decisions** (what to do) → **Automation** (doing it without manual effort)

> ⚠️ **All sample data is SYNTHETIC.** It is generated by `scripts/generate_sample_data.py` with made-up numbers
> (a fictional apparel retailer). It contains no real client or internship data. State this on your CV and in demos.

## Architecture

| Layer | What it does | Where |
|---|---|---|
| Data | Upload CSV/Excel, clean, validate (strict, clear messages), store in SQLite or PostgreSQL | `biziq/data_layer.py` |
| Intelligence | 11 modules turn data into scores, forecasts and flags | `biziq/*iq.py` |
| Decision | Plain-language recommendations; optional LLM that only sees computed numbers | `biziq/decision.py` |
| Automation | Alert rules, de-duplication, email (dry-run by default), scheduled jobs, drafts | `biziq/automation.py` |
| Interface | Streamlit dashboard, executive summary, a page per module, PDF reports | `app.py`, `biziq/ui.py`, `biziq/reports.py` |

Data flow: upload → clean/validate → module analytics → recommendations → automation rules → dashboard and weekly report.

## For small shops: BillBook

Open **Billing** after signing in: type the item, quantity and customer, tap Save. Stock goes down, credit sales go on the customer's account, and the Day book shows sales, money collected, expenses and an estimated profit for the day. Customers and dues lists who owes what and opens a pre-filled WhatsApp reminder. Every bill also feeds the analysis modules, so nobody has to build a spreadsheet. English and Hindi.
Everything the business has entered can be downloaded as CSV files from **Business profile**.

## Consultant pack

*Consultant pack* (Overview) builds a PDF and an Excel file to share with an accountant, banker or consultant: findings, how sure BizIQ is about each section, method notes and what was not checked. People sections are off by default and never include tables of individuals. It is not an audit.

## Sign-up and per-business sign-in

Each business signs up once and gets its own sign-in address (`?org=<name>`); its data stays in its own store and is there next time. Modules that do not apply to the business type show "Not applicable for your business model". Details: `docs/SECURITY.md`, `docs/BUILD_STATUS.md`.

## Platform layer (multi-user, 45 registered modules)

Beyond the original eleven analytics modules, BizIQ now has a platform layer:

* **Module registry and contract.** A new module is one file that calls `registry.register(ModuleSpec(...))`. Every result is
  checked against a contract (right name, non-empty computed facts, valid flags, no NaN) before it is shown, and a module that
  breaks the contract is isolated instead of taking the app down. See `docs/MODULE_CONTRACT.md`.
* **Thirty registered modules (14 listed here; 16 more in docs/BUILD_STATUS.md):** ProfitIQ, ReceivablesIQ, CreditIQ, ComplianceIQ, ExpenseIQ (finance and compliance);
  PricingIQ, ForecastIQ, ReturnsIQ, CampaignIQ, LoyaltyIQ (commercial); PipelineIQ, QuoteIQ, ContractIQ (sales operations);
  SupportIQ (customer service). Twelve new datasets (21 in total) come with synthetic sample files that contain deliberate problems.
* **Accounts and roles.** Business accounts, five roles (owner, admin, analyst, hr, viewer), scrypt password hashing, lockout after
  five failed logins, people modules limited to roles with `view_people`. Each organisation gets its own database.
* **Tamper-evident audit log.** Append-only (database triggers refuse UPDATE and DELETE) and hash-chained, so an edit is detected.
* **Approvals.** Anything that leaves the business is requested, reviewed by someone else, then decided, with a record.
* **Connectors.** A common `Connector` interface, file import, and column presets (including myBillBook report downloads).
* **Live integrations** (`biziq/live/`, page *Connections*): Shopify, Zoho Books, Tally, Tally-compatible XML (myBillBook export), and WhatsApp
  reminders sent only after approval. Written from public docs and tested on simulated responses; see `docs/INTEGRATIONS.md`.

Run with `BIZIQ_AUTH=0 streamlit run app.py` for a single-user demo with no login. The default turns login on.
Set `BIZIQ_PLATFORM_DB` to move the accounts/audit database (for example to a persistent disk when deploying).

```bash

```

Open the **Data** page and click **Load synthetic sample data**, or upload your own files (templates are

Run the tests: `python -m pytest -q` (54 tests).

## Using your own data

Each dataset has required and optional columns (see the Data page, or `SCHEMAS` in `biziq/data_layer.py`).
Column names are matched case-insensitively with spaces and hyphens treated as underscores. The validator:

- removes empty, title and total rows, strips text, converts `1,000` / `Rs 50` / `(5,000)` / `12,000 Dr` to numbers, parses day-first dates;
- keeps identical line-level rows (they can be real repeat sales) and the latest version of a repeated invoice/deal/quote;
- lists every row it sets aside, with its row number in your file and the reason, instead of dropping it silently;
- **blocks** a load when a required column is missing or more than 20% blank, or months are duplicated;
- warns when the balance sheet does not balance.

Modules run only when their data exists; the rest are listed as skipped. A module that fails is isolated and shown
as a red flag, so it never takes the dashboard down.

### Real-world files
Messy exports are expected: title rows, total rows, Indian number and date formats, odd encodings, multi-sheet workbooks, repeated uploads.
Rows are never dropped silently, repeat uploads can merge instead of duplicate, and the last load can be undone. See
[docs/REAL_DATA_AND_OPERATIONS.md](docs/REAL_DATA_AND_OPERATIONS.md) (also: Docker, backups, restore, health check).

## How the LLM layer avoids inventing numbers

1. Recommendations are first built from **templates over computed facts**. This is always available.
2. If `GROQ_API_KEY` (default model `llama-3.3-70b-versatile`, change with `BIZIQ_GROQ_MODEL`) or `ANTHROPIC_API_KEY` is set, an LLM may rewrite them. Groq is used if both are set; force one with `BIZIQ_PROVIDER`. The model receives **only the computed facts and flags**
   (never raw data) and is told not to calculate new figures.
3. **Every number in its answer is checked** against those facts. If any number cannot be traced, the LLM text is
   discarded and the template recommendations are used. Both paths are tested, including rejection of an invented number.

Set `BIZIQ_MODEL` to change the Anthropic model (default `claude-sonnet-5-5`). On Windows: `set GROQ_API_KEY=your_key` before `python -m streamlit run app.py`.

## Automation

- **Alerts**: reorder (with suggested quantity), anomalies, overdue receivables, tax deadlines, at-risk clients, and
  every red/amber flag. Alerts are stored and **de-duplicated** (7-day cooldown) so you are not spammed.
- **Email is DRY-RUN by default**: messages are saved as `.eml` files in `output/outbox/`. To send for real set
  `BIZIQ_SEND_EMAIL=1`, `BIZIQ_SMTP_HOST`, `BIZIQ_SMTP_PORT`, `BIZIQ_SMTP_USER`, `BIZIQ_SMTP_PASSWORD`,
  `BIZIQ_EMAIL_FROM`, `BIZIQ_EMAIL_TO` (see `.env.example`).
- **Human in the loop**: follow-up emails and purchase orders are written as drafts (`output/drafts/`) and are never sent
  or issued automatically.
- **Scheduling**: `python scripts/run_scheduler.py` (weekly report Mondays 08:00, alert check daily 09:00; edit
  `SCHEDULE`), `--once` to run everything now, or use cron / n8n / Zapier to call `biziq.automation.JOBS`.

### Measuring the "automation" claim honestly

The **Automation → Measure automation** tab holds the 8–10 recurring tasks from the build plan. Time each task manually
on a sample dataset and with BizIQ, enter the minutes, and it computes the share automated and the measured time
reduction. It reports **nothing until you enter measured numbers**. Keep the table so you can show your working.

## Assumptions and limitations (read before presenting)

- **Synthetic data**: results on the sample data demonstrate the platform; they are not findings about any real business.
- **Churn model**: logistic regression on RFM-style features; on the sample data the held-out AUC is about 0.64
  (modest). "At risk" means a ≥70% estimated probability of no purchase in 90 days.
- **Attrition risk (PeopleIQ)** is a transparent rule-based score, not a trained model (too few exits to train on).
- **Campaign uplift (SalesIQ)** uses *assumed* response rates and is labelled an estimate.
- **TaxIQ** uses configurable assumptions (GST 18%, income tax 25.17%, ITC share) and standard Indian due dates.
  Due dates are extended by the government from time to time. Verify with your CA; this is not tax advice.
- **InvestIQ** allocation templates and return ranges are illustrative planning assumptions, not predictions or
  investment advice.
- **Sentiment (BrandIQ)** is a simple word-list method; star ratings are the more reliable signal.
- **Not exercised live**: the LLM path was tested with mocked model responses (no API key or network was available when
  building), and SMTP sending was tested only in dry-run mode. Try both with your own credentials before relying on them.
- Currency is shown as `Rs` with lakh/crore formatting.

## Deploying a live demo

Push to GitHub and deploy `app.py` on Streamlit Community Cloud (add `GROQ_API_KEY` or `ANTHROPIC_API_KEY` as a secret only if you want
the LLM path). Load the synthetic data from the Data page on first run.


## Security, encryption and Postgres
Set `BIZIQ_DATABASE_URL` to use PostgreSQL (SQLite otherwise), `BIZIQ_MASTER_KEY` + `BIZIQ_ENCRYPT_DATA=1` to encrypt data at rest. Read `docs/SECURITY.md` before putting real data in: key backup, two-factor, SSO setup and the honest list of limits.
